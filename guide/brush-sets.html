    Applying color highlights with brush sets

    The i2 Notebook Web API provides brush sets, which allow your plug-in to apply color-based highlighting to chart elements. Brush sets work by mapping records to numeric brush indices, which are resolved to colors through a color range. The resulting colors appear as halos around the affected nodes and edges on the chart surface.

    Brush sets are session-only: they exist in the browser and aren't persisted to the server. Changes are lost when the page or chart is reloaded.

    Overview

    A brush set is a mapping from records to brush indices. Each brush index is a numeric value, where higher values take precedence if multiple indices apply to the same element. You provide a color range that translates those indices into CSS color strings.

    The typical workflow for using brush sets is:

    1. Create a color range that defines the mapping from brush indices to colors.
    2. Create a brush set and assign it the color range.
    3. Populate the brush set by mapping records to brush indices.
    4. Activate the brush set to apply the highlighting to the chart.

    Only one plug-in-owned brush set can be active at a time. Activating a new brush set automatically deactivates the previously active one.

    Creating a color range

    A color range defines how brush indices are translated into colors. You create one by calling createBrushColorRange() on the valueFactory, passing a ColorRangeConfig that maps brush indices to CSS color strings.

    There are two approaches to configuring a color range:

    Discrete color ranges

    For a discrete color range, provide an explicit color for every brush index you intend to use. Each index maps directly to its specified color.

    const colorRange = api.valueFactory.createBrushColorRange({
  0: '#1a9641', // Green
  1: '#a6d96a', // Light green
  2: '#ffffbf', // Yellow
  3: '#fdae61', // Orange
  4: '#d7191c', // Red
});

    Continuous (gradient) color ranges

    For a continuous color range, provide colors only at key indices. Indices that fall between the keys are interpolated linearly. This is useful when brush indices span a wide numeric range.

    // Indices 0 to 100 are interpolated between green and red
const gradientRange = api.valueFactory.createBrushColorRange({
  0: '#1a9641', // Green at index 0
  100: '#d7191c', // Red at index 100
});

    With this configuration, an index of 50 resolves to a color halfway between green and red.

    Creating and populating a brush set

    Create a brush set through the brushSets manager on the root API, then assign a color range and populate it with record mappings.

    const brushSet = api.brushSets.create();
brushSet.setColorRange(colorRange);

    Use set() to map records to brush indices. You can set a single record or provide multiple entries at once:

    // Set a single record
brushSet.set(someRecord, 4);

// Set multiple records in bulk
brushSet.set([
  [record1, 0],
  [record2, 1],
  [record3, 4],
]);

    Use remove() to remove specific records from the brush set, or clear() to remove all mappings:

    // Remove specific records
brushSet.remove([record1, record2]);

// Remove all records from the brush set
brushSet.clear();

    Activating and deactivating brush sets

    You must activate a brush set before its highlighting appears on the chart. To do so, call activate() on the brush sets manager. The brush set must have a color range assigned, or the call throws an error.

    api.brushSets.activate(brushSet);

    Only one plug-in-owned brush set can be active at a time. If another brush set is already active, it is automatically deactivated when you activate a new one.

    To remove the highlighting, call deactivate():

    api.brushSets.deactivate(brushSet);

    You can check the currently active brush set through the activeBrushSet property, which returns null if no plug-in brush set is active.

    Example

    The following example creates a brush set that highlights entities based on how many links they have, with more connected entities shown in warmer colors:

    // Create a gradient color range — 0 links is green, 10+ links is red
const colorRange = api.valueFactory.createBrushColorRange({
  0: '#1a9641', // Green — few connections
  10: '#d7191c', // Red — many connections
});

// Create and configure the brush set
const brushSet = api.brushSets.create();
brushSet.setColorRange(colorRange);

// Map each entity record to a brush index based on its link count.
// We cap the index at 10 to match the maximum value defined in our color range.
const entries: [records.IChartEntityRecord, number][] = [];
for (const record of api.chart.entityRecords) {
  const linkCount = Math.min(record.linkRecords.size, 10);
  entries.push([record, linkCount]);
}
brushSet.set(entries);

// Activate to apply the highlighting
api.brushSets.activate(brushSet);

    Resolving colors

    The brush sets manager provides two methods for resolving the effective color for records and elements:

    • getColorForRecord() returns the CSS color string for a single record, or null if it is not brushed.
    • getColorForElement() returns the CSS color string for a chart element, or null if none of its records are brushed.

    A visual element on the chart represents one or more records. When an element contains multiple records, getColorForElement() resolves the color by looking at all the constituent records and using the highest brush index.

    For example, if three records are merged into a single visual node:

    • Record A has a brush index of 2 (Yellow)
    • Record B has a brush index of 5 (Red)
    • Record C is not brushed

    Because 5 is the highest index, the entire merged node takes the color Red.

    const color = api.brushSets.getColorForRecord(recordId);
if (color) {
  console.log(`Record is highlighted with color: ${color}`);
}

const elementColor = api.brushSets.getColorForElement(elementId);
if (elementColor) {
  console.log(`Element is highlighted with color: ${elementColor}`);
}

    You can also use getColor() to get the color for a particular brush index. This is useful when you wish to color UI elements in a table to match the color of the highlighted elements.

    const color = colorRange.getColor(5);

    Note: System features like "Find items on the chart" use internal brush sets that take precedence over plug-in brush sets. If a system feature is actively brushing a record, its color is returned instead of the plug-in brush set's color.

    Listening for brush set changes

    You can listen for changes to brush sets by subscribing to the brushsetchange event on the root API. This event fires when a brush set is activated, deactivated, or when its contents change.

    api.addEventListener('brushsetchange', (brushSet, applicationContents) => {
  console.log('Brush set changed:', brushSet.id, 'Active:', brushSet.isActive);
});

    The listener receives the IBrushSet that changed.

    Lifecycle and cleanup

    Brush sets are session-only. They are not persisted to the server and are lost when the page or chart is reloaded.

    When records are removed from the chart, the application automatically purges their entries from all brush sets. If those records are later restored (for example, through an undo operation), your plug-in is responsible for re-populating the brush set with the restored records.

    To permanently remove a brush set, call delete():

    api.brushSets.delete(brushSet);

    Deleting an active brush set also removes its highlighting from the chart.
