    What's new in version 1.10

    Version 1.10 of the i2 Notebook API adds richer command groups, invocation context for commands, appearance hints for new chart elements, badges, edge summary styling, hover events, read-only chart detection, more flexible dialog sizing, and several new system commands.

    • Command invocation context — Command handlers now receive the chart position and keyboard modifier state at the point at which the command was triggered, so that a plug-in can, for example, place a new node under the cursor.
    • Dynamic command groups — Register groups whose commands are created each time the group opens, either synchronously or asynchronously.
    • Command group enhancements — Groups gain an onSurface state hook, split-button primary commands, a 'stacked' layout, ribbon-style pop-outs, and reusable group templates that you can surface into several places.
    • Appearance hints for new elements — When you add a record in a tracked mutation, you can specify the color, label, size, position, and other appearance details of the element that the system creates for it.
    • Badges — Read and set badge icons on nodes and edges.
    • Edge summary styling — Read the style of an edge summary, and override its color, direction, line style, and width.
    • Hover events — The new charthoverchange event fires when the pointer enters, leaves, or moves between chart elements.
    • Read-only charts — Detect whether the user opened the chart as a read-only snapshot.
    • Dialog sizing — Plug-in dialogs support an 'xmedium' size, custom dimensions, and automatic height.

    Root API

    IEntryPointApi

    • pluginBaseUrl — the base URL from which the plug-in's assets are served. The URL always ends with a forward slash.

    NotebookStatic

    • getEntryPointApi accepts '1.10' as an apiVersion. The bundled getEntryPointApi function now requests version 1.10.

    app namespace

    ITrackedMutations

    • createNode and createEdge — after you add an entity or link record, pass the pending record to obtain an editor that hints the appearance of the element that the system creates for it. The element is created with the hints applied, rather than first appearing with its default appearance.

    IElementEditorBase

    • setBadge and clearBadges — set or clear the badge icons on a node or edge.

    INodeEditor

    • The inherited setters (setLabel, setBadge, clearBadges) now return the node editor, so that you can chain them with node-specific setters such as setCenter, setSize, and setImage in any order.

    IEdgeSummaryEditor

    • setColor, setDirection, setLineStyle, and setWidth — override the style of an edge summary.

    chart namespace

    IChart

    • isReadOnly — whether the user opened the chart as a read-only snapshot. On a read-only chart, mutations that would change the chart are rolled back, and their promises resolve with a result that contains no changes.

    ChartEventMap

    • charthoverchange — new event that fires when the pointer enters, leaves, or moves between chart elements, but not on every pointer movement. The HoverChangeListener receives the hovered node, edge, edge summary, or node group, or null when the pointer leaves all elements.

    IRecordChanges

    • direction — present and true for link records whose direction changed.

    commands namespace

    ICommandConfig

    • onExecute now receives an ICommandInvocationContext, with triggerPosition and modifierKeys (IModifierKeys), through the new CommandExecutePayloadMap. For 'unscoped' commands, the context is an optional argument, so existing onExecute handlers that declare no parameter continue to work unchanged. An 'unscoped' handler that explicitly declares a void parameter, such as onExecute(_payload: void), no longer compiles; remove the parameter, or declare it as invocationContext?: commands.ICommandInvocationContext.

    ICommandApi

    • createGroup — returns a detached IGroupTemplate that you build once and surface into one or more action areas.

    IActionArea

    • addDynamicGroup — add a group whose commands are created each time its host surface (pop-up menu or ribbon drop-down) opens. The group's onPopulate callback receives an IDynamicActionArea, and can return a promise; the host opens the pop-up immediately with placeholder rows and shows the real items when the promise resolves.
    • surfaceGroup — surface a group template that was created with createGroup.
    • addGroup and addOrGetGroup are now generic in the command type, so that the type of a group's onSurface event API is inferred from its context.

    IGroup / IDynamicGroupConfig

    • IGroup is now a union of IStandardGroup and ICommandGroup, and IDynamicGroupConfig is a union of IStandardDynamicGroup and ICommandDynamicGroup.
    • primaryCommand — specifies a 'command' (split-button) group's primary command, which runs when users click the main part of the button. If a static group does not specify one, the first command that is surfaced in the group is its primary command, as in version 1.9. A dynamic 'command' group must specify one. No other group type can specify one.
    • onSurface — drive a group's label, icon, and enabled or hidden state from application events through an IGroupAction, in the same way as ICommandConfig.onSurface for individual commands. Disabling an expanded group also disables its immediate children.
    • context — selects the command context type for the group's onSurface event API. It is optional on static groups, where it defaults to 'unscoped'. On dynamic groups it is required, and it also determines the payload that onPopulate receives.
    • popoutStyle — on a static 'collapsed' or 'command' group, set to 'ribbon' to open a floating ribbon-style panel instead of a standard drop-down menu.

    GroupType

    • 'stacked' — displays a group's children as a vertical column of small buttons in the ribbon, which collapses under overflow pressure. In pop-up menus, the children are displayed as normal menu items below a section header.

    ISystemCommands

    • copyToNewChart
    • getMatches
    • renameChart
    • shareChart
    • toggleFindConnectingNetworks
    • toggleSocialNetworkAnalysis

    Command, group, and ribbon tab identifiers no longer need to be GUIDs. Any non-empty string is accepted, although a GUID or other globally unique value is still recommended to avoid collisions with other plug-ins.

    dialog namespace

    IDialogConfig

    • size now accepts:
      • 'xmedium' — a new preset DialogSize between 'medium' and 'large'.
      • IDialogDimensions — explicit CSS width and height lengths, each limited to the 'large' size.
      • IDialogAutoHeightSize — a preset width with height: 'auto', which makes the dialog's height fit its content.

    schema namespace

    IChartPropertyType

    • itemType — the item type that owns the property type.

    visual namespace

    IElementStyleBase

    • badges and getBadge — the badge icons on a node or edge; see IBadgeIcon and BadgeSlot.

    IEdge

    • summary — the edge summary that contains the edge, if any.

    IEdgeSummary

    • style — the style of the edge summary; see IEdgeSummaryStyle.

    Tooling

    • The SDK packages are built with TypeScript 6. The public API is unchanged.
    • The minimum supported Node.js version is now 20.19.
    • The @i2analyze/notebook-sdk package and projects that @i2analyze/create-notebook-plugin generates now include an AGENTS.md file with guidance for AI coding assistants.
    • The plug-in manifest supports an isModule field for plug-ins that are ES modules.

    Deprecations

    • ISystemCommands.saveChart: Deprecated. The system now saves charts automatically. Use renameChart to rename a chart, or shareChart to manage sharing and access control.
